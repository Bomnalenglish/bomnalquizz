# 봄날 문제은행 (오답노트)

학생별로 틀린 문항 번호를 체크하면 오답노트를 뽑아주는 **선생님용** 도구입니다.
HTML 파일 하나로 돌아가고 서버는 필요 없습니다.

- 공개 주소: <https://bomnalenglish.github.io/bomnalquizz/bomnal_bank.html>
- 관리자 사이트(`bomnalquizz_admin.html`) 탭바의 **📝 오답 문제은행 ↗** 에서도 열립니다
- 들어갈 때 선생님 코드를 묻습니다. 코드는 관리자 사이트와 같은 `bomnalvaca2025`
  (바꾸려면 `app_shell.html` 의 `var CODE = ...` 한 줄만 고치면 됩니다)
- 검색엔진에는 잡히지 않도록 `noindex` 를 걸어두었습니다.
  다만 **주소를 아는 사람은 코드 없이도 소스를 볼 수 있습니다** — 암호가 HTML 안에 들어 있기 때문입니다.
  민감한 자료라면 이 방식에 기대지 마세요.

## 폴더 구성

| 파일 | 무엇 |
|---|---|
| `app_shell.html` | 화면과 기능. **여기를 고칩니다.** 데이터 자리는 `__BANK__`, `__BUILDSTAMP__` 로 비워둠 |
| `bank.json` | 문제은행. 자료 4개 · 250문항 |
| `build.py` | 위 둘을 합쳐 완성본 HTML을 만듦 |
| `../bomnal_bank.html` | 완성본. 저장소 루트에 만들어짐 = 공개되는 파일 |

## 고치고 확인하는 법

```bash
cd bomnal_bank_src
python3 build.py                                  # 합치고 자체 점검까지
git add ../bomnal_bank.html . && git commit -m "자료 추가" && git push
```

푸시하고 1분쯤 뒤 새로고침하면 반영됩니다.
화면 맨 위 **빌드 시각**이 안 바뀌었으면 캐시가 남은 것이니 `Cmd+Shift+R` 로 강제 새로고침하세요.

`app_shell.html` 을 고칠 때마다 `build.py` 를 다시 돌리면 됩니다.
점검에서 "없는 화면 요소" 나 "빠진 함수" 가 나오면 그대로 두지 말고 고쳐야 합니다.
(전에 코드를 잘못 잘라내 PDF 읽기 함수가 통째로 사라진 적이 있어서 넣어둔 검사입니다.)

## bank.json 구조

```json
[
  { "code": "MOCK2409",
    "title": "2024년 9월 고1 모의고사 — 일치/불일치",
    "questions": [
      { "id": "MOCK2409-1", "no": 1,
        "stem": "다음 글의 내용과 일치하는 것은?",
        "passage": "As the guardian of a talented child, ...",
        "extra": "",
        "options": ["① ...", "② ...", "③ ...", "④ ...", "⑤ ..."],
        "answer": "⑤",
        "explain": "본문은 부모의 자랑이 ..." }

```

`code` 는 자료를 구분하는 열쇠입니다. 학생 체크 기록이 이 값으로 저장되므로
이미 쓰던 자료의 `code` 는 바꾸지 마세요.

## PDF 에서 문제를 뽑는 법 (pdf2bank.py)

```bash
python3 pdf2bank.py "문제지.pdf" out.json     # 문항 수·정답 수·이상한 곳을 찍어준다
```

`pdf2bank.py` 는 이 출판사(APEX) 형식의 PDF 를 문항으로 바꿉니다.
쪽 구성(문제/정답지)과 낱말 사전을 파일마다 알아서 잡습니다.
`parse.py` 는 너른터 1과 어법을 처리하던 초판이라 남겨만 둔 것입니다.
새 자료를 넣을 때 손볼 곳이 있으면 여기입니다. 겪었던 함정들:

- **2단 편집** — `pdftotext -x/-W` 로 좌·우 단을 따로 뽑아 이어붙인다. 한 번에 뽑으면 줄이 섞인다.
- **밑줄형 문제** (`밑줄 친 부분 중, 어법상 틀린 것은?`) 는 ①~⑤ 가 지문 안에 박혀 있다.
  선택지로 뽑으면 안 된다. 발문으로 구분한다.
- **한글 줄바꿈** — 이 PDF 는 한글을 낱말 중간에서도 자른다. 무조건 띄우면 "가장 적 절한",
  무조건 붙이면 "변화시킨젊은" 이 된다. `pypdf` 가 낱말 사이를 두 칸 띄우는 성질로
  낱말 사전(`vocab.json`)을 만들어 `joinln()` 에서 판정한다.
- **정답지 형식이 네 가지다** — `1번-④`, `46 번 - ⑤`, 문서 끝 각주형 `1) ⑤: 해설...`,
  그리고 주관식의 서술형 `1 번 - reminded her of ... [넓은 공백] 해설...`.
  서술형은 넓은 공백(3칸 이상)에서 답과 해설을 가른다.
  각주형은 해설 뒤에 선택지 우리말 번역이 붙으므로 `①` 이 나오는 데서 끊는다.
- **정답지 경계는 손대기 전 원문에서 찾아야 한다** — `clean()` 이 `(정답지)` 줄을 지운다.
  cleaned 된 줄에서 찾으면 경계를 못 찾아 정답이 통째로 0개가 된다 (실제로 겪음).
- **발문 끝이 파일마다 다르다** — `[1-1]` 꼬리표가 붙는 것도 있고 `것은?1)` 처럼
  각주 번호로 끝나는 것도 있다. 둘 다 끝으로 본다.
- **원본 결함** — 너른터 1과 어법 PDF 는 20번 지문이 5→6쪽 경계에서 한 구절 빠져 있다.
  같은 지문을 쓰는 21·23번과 해설로 복원해 두었다.
- 발문은 `CANON` 표준형에 맞춰 통일한다. 안 맞는 게 나오면 표에 추가한다.

## 한글(.hwp) 기출문제집 (hwp2txt.py · hwp2bank.py)

```bash
python3 hwp2bank.py "기출.hwp" out.json
```

hwp 는 OLE 복합문서다. `hwp2txt.py` 가 BodyText/SectionN 을 zlib 로 풀고
태그 67(PARA_TEXT)의 UTF-16LE 글자를 뽑는다. 한컴·LibreOffice 없이 돌아간다.

문서 구조가 APEX PDF 와 전혀 다르다.

```
다음 글을 읽고 물음에 답하시오. [1과][학교]
 <지문 — 들여쓰기>
윗글의 제목으로 가장 적절한 것은?      ← 발문, 열 0
 ⑤                                  ← 정답! 발문 바로 다음, 들여쓰기
① ...  ② ...                        ← 선택지, 열 0
```

**정답이 발문 바로 뒤에 붙어 있다.** 그냥 읽으면 문제지에 답이 그대로 노출된다.
들여쓰기로 갈라낸다 — 정답은 들여쓴 줄, 선택지는 열 0.

겪은 함정:
- 발문 끝이 `[1과][영신고]` 꼬리표나 `(단, ...)` 설명으로 끝난다. 떼고 판정한다.
- 대화 지문 `G: How was your weekend?` 이 물음표로 끝나 발문으로 오인된다.
  **발문은 한글을 포함해야 한다**는 조건으로 막는다.
- 문서 제목 줄(`... 내신기출문제 – 138문항`)이 첫 지문에 섞인다.
- 한 지문을 여러 문항이 함께 쓴다. 세트 머리말부터 다음 세트까지 같은 지문을 물린다.
- 문항 번호가 문서에 없다. 차례대로 매긴다.

## 문제는 어떻게 넣는가

**앱 안에서 넣지 않습니다.** 원본 파일을 대화로 넘기면 문제·선택지·정답·해설을
갈라서 `bank.json` 에 직접 넣습니다. 각 자료에는 `group`(폴더)을 꼭 붙입니다.

예전에는 화면에 붙여넣기·PDF 불러오기 칸이 있었지만 걷어냈습니다.
정답 분리가 파일 안의 `(정답지)` 문자열 하나에만 의존해서 `정답 및 해설`·`[정답]` 같은
다른 표기를 못 읽었고, 실패하면 해설이 **다음 문항의 지문으로 흘러들어가**
오답노트에 답이 그대로 노출됐기 때문입니다.
그 화면과 파서, pdf.js(1.5MB)를 함께 뺐고 완성본은 1.92MB → 0.46MB 로 줄었습니다.
되살리려면 `git show 38d3d88:bomnal_bank_src/app_shell.html` 에 예전 판이 있습니다.

## 폴더

**두 단계까지** 됩니다. 경로는 `"종촌고1"` 또는 `"종촌고1/교과서"` 처럼 `/` 로 잇습니다.
화면에는 `종촌고1 › 교과서` 로 보입니다. 폴더 이름 자체에는 `/` 를 못 씁니다(자동으로 공백이 됨).

- **폴더 만들기** — 상위 폴더를 고르고 이름을 적으면 그 아래에 생깁니다 (`store.folders`)
- **이름 수정** — 폴더 제목이 곧 입력칸입니다. 고쳐 쓰고 Enter.
  상위를 바꾸면 그 아래 하위 경로도 함께 따라갑니다 (`renameFolder` 의 `remap`).
  이미 있는 이름으로 바꾸면 두 폴더가 합쳐집니다.
- **자료 이동** — 자료 옆 드롭다운 (`store.folder[code]`)
- **폴더 지우기** — 비어 있는 폴더에만 버튼이 나옵니다
- **기본 폴더로 되돌리기** — 이 브라우저에 남은 이동 기록을 지우고
  `bank.json` 의 `group` 대로 돌립니다. 이동 기록이 있을 때만 버튼이 나옵니다

관련 함수: `topOf` / `subOf` / `showPath` / `allFolders` / `renameFolder` / `folderHead`

이 셋(`folders`·`folder`·`closed`)은 모두 **그 브라우저에만** 남습니다.
모두에게 같게 보이려면 `bank.json` 의 `group` 값에 경로를 넣어야 합니다.

## 대화상자(alert·confirm·prompt)를 쓰지 않는다

환경에 따라 `prompt()` 는 "not supported" 예외를 던지고 `confirm()` 은 무조건 `false` 를
돌려주는 경우가 있다. 그러면 폴더 이동과 삭제가 **아무 반응 없이 조용히 실패한다.**
실제로 이 문제로 폴더 이동이 안 됐던 적이 있으므로 새 기능을 넣을 때도 쓰지 말 것.

- 폴더 이동 → 자료 옆 **드롭다운**
- 삭제 · 오답 전체 지우기 → **한 번 더 누르기** (4초 뒤 원래대로)
- 이름 바꾸기 → 위의 이름칸에 적고 버튼
- 안내문 → `#stuMsg`, `#srcMsg`, `#printMsg` 에 글자로 표시

## 알아둘 제약

- **인쇄는 새 탭에서.** 관리자 사이트에 iframe 으로 끼워 넣으면 `app_shell.html` 이
  이를 감지해 인쇄 창을 막고 파일 내려받기로 돌립니다. 그래서 탭바 링크를
  `target="_blank"` 새 탭으로 열도록 해두었습니다.
